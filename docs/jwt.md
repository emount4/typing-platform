# JWT: Python выпускает, Go проверяет

Самый короткий контракт в каталоге и самый неприятный при расхождении: одно лишнее поле
или другой алгоритм — и все авторизованные забеги молча становятся анонимными, без единой
ошибки в логах.

## Общее

* Алгоритм — **HS256**. Секрет один на оба сервиса, из переменной окружения `JWT_SECRET`
  (в Go сейчас читается как `SECRET` — переименовать). В репозитории лежит только
  `.env.example` со значением `dev-secret-change-me`.
* Go проверяет подпись **локально**, без сетевого запроса на каждое сообщение.
* Go проверяет: подпись, `exp`, `nbf` (если есть), `typ == "access"`. Ничего больше.
* Go **не знает об отзыве токенов**: заблокированный пользователь живёт по своему
  access-токену до 15 минут. На нынешнем масштабе приемлемо. Когда перестанет быть —
  Python кладёт заблокированных в Redis, Go сверяется.

## Access-токен · stable · этап 3

```json
{
  "sub": "42",
  "user_id": 42,
  "login": "matvey",
  "typ": "access",
  "iat": 1786000000,
  "exp": 1786000900
}
```

| Claim | Тип | Кто использует |
|---|---|---|
| `sub` | `string` | стандартный, для совместимости с библиотеками |
| `user_id` | `int64` | **читает Go**, дублирует `sub` числом, чтобы не парсить строку в каждом соединении |
| `login` | `string` | Go подставляет в `room.state` и логи |
| `typ` | `string` | `access`; всё, что не `access`, Go отвергает |
| `exp` | `int` | +15 минут от `iat` |

Дублирование `sub` и `user_id` — сознательное. `sub` по RFC 7519 обязан быть строкой,
а Go нужен `int64`; договориться один раз дешевле, чем ловить `json: cannot unmarshal
string into int64` в проде.

## Refresh-токен · stable · этап 3

```json
{ "sub": "42", "typ": "refresh", "jti": "8f3c...", "iat": ..., "exp": ... }
```

Живёт 30 дней, хранится в БД по `jti` с возможностью отзыва, ходит только в
httpOnly-cookie и **никогда не попадает в Go**. Если Go увидел `typ: "refresh"` —
сессия анонимная, в лог `WARN`: это либо баг фронтенда, либо попытка обойти проверку.

## Что происходит при расхождении

| Ситуация | Поведение Go | Видит пользователь |
|---|---|---|
| Секреты разошлись | подпись не сходится → аноним | забеги не сохраняются, ошибок нет |
| Python выпустил `HS512` | алгоритм не тот → аноним | то же самое |
| `user_id` уехал в строку | claims не разбираются → аноним | то же самое |

Во всех трёх случаях симптом один и отладке не поддаётся. Поэтому в CI живёт тест:
Python выпускает токен фикстурного пользователя, Go его проверяет и достаёт `user_id: 42`.
Гоняется на каждый PR, трогающий `security/jwt.py` или `internal/auth/`.
