# Внутренний контракт: Go → Python

Канал: **Go realtime → Python API**, HTTP внутри docker-сети.
База: `http://api:8000`. Наружу **не выставляется** — Caddy про путь `/internal/*` не знает.

Направление всегда одно: **Go обращается к Python, Python не обращается к Go никогда.**
Единственное исключение — генератор упражнений (`generator.md`), он с realtime не связан.

Версия документа: **v1**, 13.08.2026.

---

## 1. Общие правила ✅

**Аутентификация.** Заголовок `X-Internal-Token` со статическим секретом из `.env`.
Нет заголовка или не совпал — `403`, тело `{"detail": "forbidden"}`.

Основная защита при этом — **не токен, а недостижимость `/internal/*` снаружи**. Токен
нужен от соседа по docker-сети и от ошибки в Caddyfile, а не от интернета. Проверять его
надо константным сравнением (`secrets.compare_digest`), а не `==`.

**Формат.** JSON в обе стороны, `snake_case`, `Content-Type: application/json`.

**Таймауты.** Go ждёт ответа **5 секунд**. Дольше — ошибка, забег уходит в очередь
`pending_runs`.

**Идемпотентность.** `POST /internal/runs` и `/internal/races` идемпотентны по
`session_id` / `race_id`: повторный запрос с тем же идентификатором возвращает `200`
и **тот же** результат, не создавая второй записи.

Это обязательное требование, а не пожелание. Ретраи из `pending_runs` неизбежно будут
дублировать запросы: типичный случай — Python записал забег и умер до отправки ответа.
Без идемпотентности пользователь получит два личных рекорда за один забег.

**Коды ответов.**

| Код | Значение | Что делает Go |
|---|---|---|
| `200` | Обработано (в т.ч. повторно) | Дальше по сценарию |
| `201` | Создано | Дальше по сценарию |
| `403` | Токен не тот | Логирует, **не ретраит** — это баг конфигурации |
| `404` | Объекта нет | `error` клиенту, не ретраит |
| `422` | Тело не прошло валидацию | Логирует, **не ретраит** — это расхождение контракта |
| `5xx` | Python упал | Ретрай с нарастающей задержкой |

`422` не ретраится намеренно: если тело не проходит валидацию, оно не пройдёт её и через
минуту. Такой ответ должен шуметь в логах, а не тихо копиться в очереди.

## 2. `GET /internal/texts/{text_id}` ✅

Этап 2. Go забирает эталонный текст в начале забега.

**Запрос:** `GET /internal/texts/8f14e45f-ceea-467a-9f0a-1c3bd0a3f7d2`

**Ответ `200`:**

```json
{
  "id": "8f14e45f-ceea-467a-9f0a-1c3bd0a3f7d2",
  "content": "Осень в этом году пришла рано...",
  "lang": "ru",
  "length": 247,
  "source": "public_domain"
}
```

| Поле | Тип | Описание |
|---|---|---|
| `id` | string (UUID v4) | |
| `content` | string | Эталон. Нормализован в **NFC** |
| `lang` | enum | `ru` \| `en` |
| `length` | int | Длина в графемах. Go сверяет со своим подсчётом |
| `source` | string | Происхождение — для лицензионной чистоты |

**Нормализация — часть контракта.** «й» существует в двух видах: одним кодепойнтом (NFC) и
как «и» + комбинирующая бреве (NFD). Выглядят одинаково, сравниваются как разные. Если
Python отдаст NFD, а браузер пришлёт NFC, каждая «й» в тексте будет считаться ошибкой, и
искать причину придётся долго. Python нормализует при записи в базу, Go доверяет.

**Кэш.** Go кэширует ответ в памяти по `text_id` (тексты неизменяемы). При изменении текста
в базе Python обязан выдать **новый** `id`, а не переписать существующий: иначе у Go
останется старый эталон, и забеги начнут считаться по несуществующему тексту.

**Ошибки:** `404` — текста нет → Go шлёт клиенту `error` с `text_not_found`, `fatal: true`.

## 3. `POST /internal/runs` ✅

Этап 2. Итог забега. Самый нагруженный контракт проекта — сюда уезжает всё, из чего
потом строятся статистика, лидерборды и учебный режим.

### 3.1. Запрос

```json
{
  "session_id": "01J9X8K2M4P7Q1R3S5T7V9W2Y4",
  "user_id": 17,
  "anon_id": null,
  "text_id": "8f14e45f-ceea-467a-9f0a-1c3bd0a3f7d2",
  "mode": "solo",
  "started_at": "2026-08-13T18:42:11.418Z",
  "duration_ms": 47320,
  "wpm_net": 62.4,
  "wpm_raw": 65.1,
  "accuracy": 95.8,
  "typed": 253,
  "correct": 242,
  "errors": 11,
  "flags": [],
  "keystrokes": [
    { "char": "О", "t": 0, "is_error": false },
    { "char": "c", "t": 143, "is_error": true },
    { "char": "Backspace", "t": 289, "is_error": false },
    { "char": "с", "t": 401, "is_error": false }
  ]
}
```

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `session_id` | string | да | Ключ идемпотентности |
| `user_id` | int64 \| null | да | `null` для анонима |
| `anon_id` | string \| null | да | UUID браузера. Заполнен ⟺ `user_id: null` |
| `text_id` | string | да | |
| `mode` | enum | да | `solo` \| `race` \| `lesson` |
| `started_at` | string | да | ISO 8601 UTC, момент `session.started` по часам Go |
| `duration_ms` | int | да | От первого нажатия до последнего |
| `wpm_net`, `wpm_raw` | float | да | Формулы — `websocket.md` §3.4 |
| `accuracy` | float | да | Проценты, 0–100 |
| `typed`, `correct`, `errors` | int | да | |
| `flags` | string[] | да | Пустой массив, если чисто |
| `keystrokes` | object[] | да | Сырой поток в порядке нажатия |

**`user_id: null` вместо `0`.** Ноль — валидный `int64` и в базе он превратится либо в
несуществующего пользователя, либо в внешний ключ на пустоту. `null` отличает «анонима»
от «пользователя номер ноль» явно.

> ⚠️ Сейчас Go шлёт `UserID: 0` для анонимов, а поле `IsAnon` в `RunResult` не попадает
> вовсе — Python не может отличить анонима от сбоя аутентификации.

**Никакого `is_personal_best` в запросе.** Считает и возвращает его Python — только он
видит историю пользователя.

### 3.2. Агрегаты: считает Python

Go отдаёт **сырой поток**, Python строит `run_key_stats` и `run_bigram_stats` в той же
транзакции, что и сам забег.

Причины, по которым выбрано так:

- **Схемой владеет Python** (решение 2.2). Агрегаты — это форма таблиц, а не поведение
  сессии. Если их считает Go, то при добавлении, скажем, триграмм менять придётся оба сервиса
  и договариваться о формате — то есть ровно то, чего решение 2.2 избегает.
- **Сырой поток нужен независимо** — для реплеев и гонки с «призраком» (решение 2.4).
  Раз он всё равно передаётся, отдельно передавать ещё и агрегаты — дублирование, которое
  рано или поздно разъедется.
- **Пересчитать задним числом можно только из сырого потока.** Формулу WPM или определение
  «проблемной связки» захочется поменять; агрегаты, посчитанные по старой, к тому моменту
  уже необратимы.

Цена — размер тела: забег на 250 символов ≈ 12 КБ JSON. Внутри docker-сети это ничто.

Хранение сырого потока — на стороне Python по решению 2.4: последние N забегов и личные
рекорды целиком, остальные — только агрегаты.

### 3.3. Флаги

Значения `flags[]`. Список расширяется на этапе 5, поэтому Python **игнорирует
неизвестные значения**, а не падает на них.

| Флаг | Смысл |
|---|---|
| `non_monotonic_time` | Метки времени не возрастали |
| `interval_below_minimum` | Интервал меньше 15 мс |
| `low_interval_variance` | ⚪ этап 5: слишком ровный ритм — человек так не печатает |
| `perfect_at_high_speed` | ⚪ этап 5: 100% точности на аномальной скорости |
| `no_slowdown_on_rare_bigrams` | ⚪ этап 5: нет замедления на редких связках |

Забег с непустым `flags` **сохраняется**, но не попадает в лидерборды и остаётся виден
владельцу. Помечать, а не блокировать: первые недели пороги подбираются по живой статистике
ложных срабатываний, и заблокированные настоящие пользователи в этот момент — цена,
которую платить не за что.

### 3.4. Ответ `201`

```json
{
  "run_id": "b2f4c8a1-3d5e-4f70-9a1b-2c3d4e5f6a7b",
  "is_personal_best": true,
  "flagged": false,
  "rating_delta": null
}
```

| Поле | Тип | Описание |
|---|---|---|
| `run_id` | string (UUID) | |
| `is_personal_best` | bool | Считает Python по истории пользователя |
| `flagged` | bool | Итоговое решение Python (может добавить свои проверки к `flags`) |
| `rating_delta` | float \| null | Всегда `null` для `solo`. Заполняется для `race` с этапа 5 |

Эти поля Go пересылает клиенту в `session.saved`.

## 4. `POST /internal/races` ⚪

Этап 4. **Эскиз.** Итоги заезда: одна запись `races` + N записей `race_participants`,
пересчёт рейтинга, ответ с дельтами по каждому участнику.

```json
{
  "race_id": "01J9X8...",
  "room_code": "K7X2M9",
  "text_id": "8f14e45f-...",
  "started_at": "2026-08-13T18:42:11.418Z",
  "finished_at": "2026-08-13T18:43:58.902Z",
  "participants": [
    { "user_id": 17, "place": 1, "finished": true,  "session_id": "01J9X8A...", "wpm_net": 71.2, "accuracy": 97.1, "duration_ms": 41200, "typed": 253, "correct": 246, "errors": 7, "flags": [], "keystrokes": [] },
    { "user_id": 23, "place": 2, "finished": false, "session_id": "01J9X8B...", "wpm_net": 58.9, "accuracy": 92.4, "duration_ms": 47100, "typed": 198, "correct": 183, "errors": 15, "flags": [], "keystrokes": [] }
  ]
}
```

Ответ — `race_id`, и по каждому участнику `run_id`, `rating_before`, `rating_after`,
`rating_delta`, `is_personal_best`.

Один запрос на весь заезд, а не N штук на `/internal/runs`: рейтинг считается по парам
участников, и для этого нужны все результаты сразу, в одной транзакции.

Открытый вопрос к этапу: попадает ли забег из гонки ещё и в личную статистику как обычный
run (предлагается — да, `mode: "race"`, чтобы статистика по клавишам копилась во всех
режимах, как и задумано в разделе 3 документации).

## 5. Общие ключи Redis ✅ / ⚪

Redis пишут и читают **оба сервиса**, поэтому схема ключей — такой же контракт, как HTTP,
и живёт здесь же. Расходятся такие вещи молча и обнаруживаются на проде.

| Ключ | Тип | Кто пишет | Кто читает | TTL | Этап |
|---|---|---|---|---|---|
| `pending_runs` | List | Go | Go | — | 2 🟡 |
| `session:{session_id}` | Hash | Go | Go | 30 с | 3 🟡 |
| `room:{code}` | Hash | **Python** | **Go** | 2 ч | 4 ⚪ |
| `leaderboard:wpm` | ZSet | Python | Python | 60 с | 3 🟡 |
| `blocked_users` | Set | Python | Go | — | 5 ⚪ |

`room:{code}` — единственное место, где Python пишет, а Go читает. Именно так комната
создаётся через REST (`POST /api/v1/rooms`), а живёт в Go, при том что Python не имеет
права звонить в Go. Состав полей фиксируется перед этапом 4:

```
text_id, mode, max_participants, created_by, created_at, status
```

`blocked_users` закрывает известную дыру из раздела 4.3: Go не знает об отзыве токенов,
и заблокированный пользователь доживает по своему access-токену до 15 минут. Пока масштаб
это позволяет — не делаем.

## 6. Что поменять в текущем коде

| # | Файл | Проблема |
|---|---|---|
| 1 | `apiclient/client.go` | `RunResult` не содержит `keystrokes` — агрегатов в базе не будет |
| 2 | `apiclient/client.go` | `is_personal_best` в запросе; ответ `SubmitRun` не разбирается |
| 3 | `apiclient/client.go` | Нет `session_id` — нечем обеспечить идемпотентность ретраев |
| 4 | `apiclient/client.go` | Нет `mode`, `flags`, `started_at`, `anon_id`, `wpm_raw`, `typed`, `correct` |
| 5 | `apiclient/client.go` | Анонимы уезжают как `user_id: 0` |
| 6 | `apiclient/client.go` | Нет очереди `pending_runs`: при недоступности Python забег теряется молча |
| 7 | `config/config.go` | `INTERNAL_TOKEN` с дефолтом `dev_secret` — на проде поднимется с ним же, если забыть переменную. Убрать дефолт, сделать `required` |
| 8 | `config/config.go` | `USE_MOCK_API` по умолчанию `true` — прод по умолчанию не пишет в базу. Дефолт должен быть `false` |

Пункты 7 и 8 — единственные два места во всём разборе, где неверный дефолт тихо выживает
до продакшена. Остальное падает или шумит.
